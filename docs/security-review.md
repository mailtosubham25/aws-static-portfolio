# Security review and remediation register

**Reviewed:** 2026-11-20  
**Scope:** Current Terraform configuration on `main` after PR #2; latest verified scan: GitHub Actions CI [run #20](https://github.com/mailtosubham25/aws-static-portfolio/actions/runs/44641593577).

**Scan result:** Checkov 3.4.6 — 31 passed, 12 failed. Trivy config scan — two HIGH findings (AWS-0011 and AWS-0132); Trivy secret scan — no issues detected. CI run #20 and deploy run [#2](https://github.com/mailtosubham25/aws-static-portfolio/actions/runs/44641593532) completed successfully.

This register reflects the Terraform configuration for a static portfolio served from a private, versioned S3 bucket through one CloudFront distribution and OAC. S3 public access block is fully enabled, objects use SSE-S3 (AES256), CloudFront redirects viewers to HTTPS, and the AWS-managed SecurityHeadersPolicy is attached. There is no configured backend, upload/event-processing workflow, second origin, custom domain certificate, or stated regional disaster-recovery objective.

A scanner **failure** means the configuration does not meet that rule's policy. It does not by itself prove an exploitable vulnerability or that a service is required. “Exception” means the control is intentionally out of scope for the current design; “defer” means retain the finding until its review trigger. Reconsider deferred items when the trigger occurs.
